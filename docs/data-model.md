# Модель данных

Приложение хранит данные локально в SQLite. Android и Windows используют одну структуру базы. Идентификаторы генерируются на устройстве, поэтому резервную копию можно перенести на другое устройство.

## Текущая схема: версия 2

### `projects`

`id`, `name`, `archived`. Проект содержит несколько тарифов.

### `rates`

`id`, `project_id`, `name`, `cents_per_hour`, `currency`, `archived`. Сумма хранится в центах за час. Смена сохраняет снимок выбранной ставки, чтобы прежний расчёт не менялся при будущей правке тарифа.

### `shifts`

`id`, `project_id`, `rate_id`, `status`, `planned_start_ms`, `planned_end_ms`, `pre_check_in_ms`, `confirmed_ms`, `credited_start_ms`, `checked_out_ms`, `credited_end_ms`, `break_minutes`, `rate_name_snapshot`, `rate_cents_snapshot`, `currency_snapshot`.

Состояния: `planned`, `armed`, `active`, `completed`, `cancelled`. Поля времени содержат миллисекунды с Unix epoch. Время предварительного check-in, подтверждения и check-out записывается отдельно от времени, по которому считаются оплачиваемые часы.

### `shift_events`

`id`, `shift_id`, `kind`, `recorded_ms`, `credited_ms`, `details_json`. События планирования, check-in, подтверждения и check-out сохраняются как исходные отметки. Исправление добавляет новое событие `corrected`; в `details_json` находятся причина и значения `before`/`after`. Прежние события не переписываются.

## Правила

- Конец плана должен быть позже начала. Для завершённой смены оплачиваемый конец должен быть позже начала; перерыв не может превышать длительность смены.
- Тариф при check-in или исправлении должен принадлежать проекту смены.
- Отчёты и CSV вычисляются из текущих исправленных значений смены; история хранит исходные и предыдущие значения.
- При открытии базы версии 1 добавляется поле `details_json` без удаления записей.
- Резервная копия имеет формат версии 2. Импорт принимает также копии версии 1, проверяет связи и заменяет данные в транзакции. Файл не зашифрован.

## Дальнейшее развитие

Смена тарифа внутри одной смены, отдельные интервалы перерывов, заметки и автоматическая синхронизация пока не входят в текущую схему. Для них понадобятся отдельные миграции и правила расчёта.
