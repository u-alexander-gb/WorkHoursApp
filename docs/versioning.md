# Нумерация выпусков

Единственный источник номера версии — поле `version` в `pubspec.yaml`.
Формат: `MAJOR.MINOR.PATCH[-beta.N]+BUILD`.

- `MAJOR.MINOR.PATCH` — версия функций приложения.
- `beta.N` — предварительный выпуск; отсутствие суффикса означает стабильный.
- `BUILD` — целое число, которое увеличивается для каждой новой Android
  сборки, предлагаемой пользователям. Не используйте старый номер повторно.
- Git тег и GitHub Release: `vMAJOR.MINOR.PATCH[-beta.N]`.
- Имя скачиваемого файла содержит тег, платформу и тип подписи.
- Перед публикацией проверьте совпадение версии в `pubspec.yaml`, тега,
  release notes и артефактов. Зафиксируйте проверенный commit.

| Выпуск | Build | Git tag | Статус |
| --- | ---: | --- | --- |
| 0.1.0 | 1 | — | Прототип, не опубликован |
| 0.2.0-beta.1 | 2 | `v0.2.0-beta.1` | Первый публичный beta выпуск |
| 0.2.0-beta.2 | 3 | `v0.2.0-beta.2` | Подписанная release APK, исправлены язык и About |

Следующий предлагаемый номер: `0.2.0-beta.3+4`. Перед каждым выпуском проверьте
реестр и увеличьте `BUILD`, даже если изменяется только номер beta.

## Подпись Android начиная с beta.2

Постоянный release ключ хранится локально в игнорируемом Git файле
`android/workhours-release.jks`; пароль — в `android/key.properties`, копия ключа
для CI — в GitHub Actions Secrets. Эти файлы нужно сохранить отдельно в
надёжном месте. Если ключ потеряется, обновить установленное приложение с тем
же Android package ID обычным способом не получится.

Отпечаток сертификата SHA-256:
`46:5A:A4:A9:B7:E4:95:65:A3:66:37:CC:CE:62:7E:55:D2:37:5C:F8:CC:DB:AE:4E:15:EB:77:9F:C7:59:40:99`.
Сверяйте его перед публикацией каждого будущего APK.
